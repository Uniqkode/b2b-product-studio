# Guide completion after the product revision

The ten products now include the buildable content and interactive features missing in the audit: problem and solution pages, a combined legal route, a specific Why now, three measurable outcome definitions, market segments/country/distribution/growth strategy, three commercial plans, clear model/evaluation/compute paths, platform infrastructure roles, named maintainer bio, visible product progress, and a guided workflow.

Each site has an independent domain explorer and editable value plan. The enquiry form now prepares an explicit, consented message handoff instead of presenting the local planning brief as the sales enquiry. Actual sending takes place on GitHub or through a verified configured inbox. Verified booking links can be enabled without shipping a placeholder calendar. SVG icons replace unsupported arrow characters, and WOFF2 reduced the source font collection from 3,556 KB to 1,181 KB.

The actual business facts remain configurable in OWNER_SETUP.md and src/company-profiles.json: owned domains, monitored mailbox, genuine legal name/registration, actual team roles/bios/professional links, booking link and measured usage. They are unpublished while unverified. The optional measured-volume block requires a complete, dated reporting record; it never invents active customers, processing or latency figures.

The Azure stack is expressed as a sector-specific operating plan. The model adapter is implemented; actual cloud resources, sector models, data ingestion, tenant identity and live metrics still require configuration/evaluation. Each standalone kit includes its own product-restricted Node model adapter and an Azure Static Web Apps deployment example.

All 32 source/backend/arithmetic test groups and 286 DOM interaction groups passed. The new tools were exercised in live desktop Chrome across all ten products. Phone-sized viewport/device verification and a formal performance benchmark remain outstanding. Interactive product tours and review views are supplied; no recorded customer footage, testimonial or pilot result is invented.

The existing shared public repository and owner-private Sites destination are the publication targets. All ten independent local Git folders are refreshed with their histories preserved. Their separate remote repositories remain unavailable to the GitHub connection and cannot be claimed as pushed.
